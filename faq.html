General Questions

Learn the basics about Flyto workflow automation

What is Flyto?

Flyto is a git-native workflow automation platform. It allows you to define workflows in YAML, compose them from atomic modules (small, single-purpose building blocks), and run everything locally without depending on external cloud services. The core is open source and available on GitHub.

What are atomic modules?

Atomic modules are small, stateless, single-purpose components that do exactly one thing well. Examples include: downloading a file, clicking a browser element, parsing HTML, or converting image formats. They're designed to be composable - you combine them in workflows to build complex automations while keeping each piece simple and testable.

How is Flyto different from other automation tools?

Key differences include: (1) Git-native - workflows are stored in git, enabling version control and collaboration; (2) Local-first - runs on your infrastructure with no cloud dependency; (3) Zero-coupling modules - components don't depend on each other; (4) AI-powered evolution - the system can propose and test improvements automatically; (5) Open source core - transparent, auditable, and community-driven.

Is Flyto open source?

Yes! The core engine (flyto-core) is fully open source and available on GitHub. This includes all atomic modules, the workflow engine, and base classes. Pro features like AI evolution and advanced knowledge routing are available in paid plans.

Technical Questions

Implementation details and technical specifications

What are the system requirements?

Flyto runs on Python 3.9+ and supports Linux, macOS, and Windows. For browser automation modules, you'll need Chrome or Chromium installed. The system is designed to be lightweight - a basic setup requires minimal resources, though complex workflows with many concurrent tasks will benefit from more CPU and memory.

How do I create custom modules?

Custom modules extend the BaseModule class and implement two key methods: validate_params() for input validation and execute() for the main logic. Register your module with the @register_module decorator. See our documentation for detailed examples and best practices.

Can I run Flyto in a Docker container?

Yes, Flyto works great in Docker. We provide official Docker images, and you can also build custom images. For browser automation, use the provided images that include headless Chrome. Docker Compose templates are available for multi-container setups.

Does Flyto support scheduled workflows?

Yes, workflows can be scheduled using cron expressions or interval-based triggers. You can also trigger workflows via webhooks, file system changes, or API calls. The scheduler supports complex patterns including dependencies between workflows.

Licensing & Pricing

Plans, pricing, and license management

What's included in the free plan?

The free plan includes access to all open source modules, unlimited workflows, and community support. It's perfect for individuals and small projects. You can run everything locally without any account or cloud connection. The only limitations are advanced Pro features like AI evolution and priority support.

What's the difference between Cloud and Offline licenses?

Cloud plans are subscription-based and include managed infrastructure, automatic updates, and cloud-based features. Offline licenses are one-time annual purchases that let you deploy Flyto on your own infrastructure with no internet requirement - ideal for air-gapped environments, regulated industries, or organizations that need full data control.

Can I upgrade my plan later?

Yes, you can upgrade at any time. For Cloud plans, we prorate the difference. For Offline licenses, contact our sales team to discuss upgrade options. Downgrading is also possible at the end of your billing period.

Do you offer educational or non-profit discounts?

Yes! We offer significant discounts for educational institutions, non-profits, and open source projects. Contact us at sales@flyto.io with details about your organization to learn more.
